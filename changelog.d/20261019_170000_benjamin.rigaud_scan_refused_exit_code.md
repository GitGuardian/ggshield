### Fixed

- A scan the GitGuardian API did not perform now fails instead of reporting "No
  secrets have been found" and exiting 0, in every `secret scan` command, `ci`
  and the git hooks included. A rate limit, a gateway or firewall error, a
  timeout or a 5xx exits with code 4, which `--no-fail-on-server-error` can
  skip. A 403 (IP allowlist, proxy, firewall) exits with code 128, which it
  cannot. A 400 still skips the rejected files, as before.
- Commit scans (`ci`, the git hooks, `commit-range`, `changes`, `repo`) now fail
  with exit code 128 when a batch of commits hits an unexpected error, instead
  of showing the error and exiting 0.
- Secrets found before the API failed to scan other files are now reported
  (exit code 1) instead of being discarded with the error. The failure is listed
  in the `errors` of the JSON report.
