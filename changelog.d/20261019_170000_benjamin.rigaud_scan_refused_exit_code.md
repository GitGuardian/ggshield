### Fixed

- A scan the GitGuardian API did not perform now fails instead of reporting "No
  secrets have been found" and exiting 0. A rate limit, a gateway or firewall
  error, or a timeout exits with code 4, which `--no-fail-on-server-error` can
  skip. A 403 (IP allowlist, proxy, firewall) exits with code 128, which it
  cannot. A 400 still skips the rejected files, as before.
- Secrets found in some files are now reported even when the API failed to scan
  other files of the same command, instead of being discarded with the error.
